# Gemini API 计费指南：从免费套餐到即用即付的保姆级教程

## 前言

最近，我在使用 Gemini API 时遇到了一个常见的错误：

> "You exceeded your current quota... Quota exceeded for metric: generativelanguage.googleapis.com/generate_content_free_tier_requests, limit: 50"

这个错误提示我“超过了免费套餐的请求配额”。这让我对 Gemini API 的计费和限额策略产生了许多疑问：

* 我订阅了 Gemini，为什么还会有配额限制？
* “免费套餐”、“免费试用”和“即用即付”到底有什么区别？
* 我该如何设置，才能既保证 API 正常使用，又避免产生高额账单？

在这篇指南中，我将分享我从摸索到弄懂的全过程，希望能帮助你彻底厘清 Google Cloud 和 Gemini API 的计费逻辑。

## 一、 问题的根源：详解“免费套餐” (Free Tier) 的双重限制

我收到的 `free_tier_requests` 错误，根源在于我的项目当时处于**“免费套餐” (Free Tier)** 状态。在这种状态下，Google 会为你提供**每日**的免费用量，但有非常严格的限制。

你需要登录到你的 Google Cloud Console 配额页面，找到 `generativelanguage.googleapis.com` (即 Gemini API)，你会看到两项关键的免费限制（你必须**同时**满足这两项）：

1.  **`Request limit per model per day for a project in the free tier`**
    * **中文含义：** 免费套餐中，每个项目、每个模型**每日的请求次数限制**。
    * **直白地说：** 这就是你一天总共能调用 API **多少次**。比如限制是 500 次，那你第 501 次调用就会失败。

2.  **`GenerateContent free tier input token count limit per model per day`**
    * **中文含义：** 免费套餐中，每日的“生成内容”**输入令牌总数限制**。
    * **最易混淆的点：** `Input token` 指的是**“输入”令牌**，而不是“输出”（答案）。
    * **直白地说：** 这限制的是你一天之内**所有“问题”加起来的总字数（令牌数）**，而不是 AI 生成了多少答案。如果你每次都问很长的问题（比如上传文档），你可能请求次数（第1项）还没用完，但“问题”的总字数已经超标了，API 同样会停止响应。

## 二、 彻底厘清三个“免费”：套餐、试用与即用即付

这是最容易混淆的部分。Google Cloud 的“免费”分为三种，它们的逻辑**完全不同**，且**互相独立**。

### 1. 免费套餐 (Free Tier)
* **这是什么？** 这是 Google 提供的“始终免费”服务。
* **如何计费？** 永不计费。
* **限制是什么？** 限制非常严格，就是上一节提到的“每日请求次数”和“每日输入令牌数”。一旦用完，当天就无法再使用，必须等第二天重置。
* **适用人群：** 轻度爱好者、学习者，用量极低的用户。

### 2. 免费试用 (Free Trial)
* **这是什么？** 这是你新注册 Google Cloud 时，Google 赠送给你的一笔**信用额度**（例如 $300 赠金，有效期 90 天）。
* **如何计费？** 你所有的使用都会被计费，但费用会**从 $300 赠金中自动扣除**，直到赠金用完或 90 天到期。
* **限制是什么？** 在试用期间，你**不再受“免费套餐”的每日限制**。你将立刻升级到“即用即付”用户的高配额（例如每分钟几千次请求）。你唯一的“限额”就是那 $300 赠金。
* **适用人群：** 新用户，需要短期测试 API 高性能的开发者。

### 3. 即用即付 (Pay-as-you-go)
* **这是什么？** 这是指你的“免费试用”已结束，或者你主动升级，你的项目正式绑定了信用卡，开始为你的**所有用量**付费。
* **如何计费？**
    * **这是最危险的误区！** 开启“即用即付”后，你**不再享有“免费套餐”的每日免费额度**。
    * 你的账单将**从 $0.00 开始计算**，你使用的**第一个请求、第一个令牌**都会被计入账单。
    * “免费套餐”和“即用即付”是**二选一**的模式，绝非“先用完免费的再付费”。
* **限制是什么？** 你获得了很高的 API 配额（如 2000 RPM），并且可以根据需求**申请提高**。你唯一的“限制”就是你的预算。
* **适用人群：** 严肃的开发者、所有需要正式上线的应用。

### 旁枝问题：Gemini 订阅和 API 代理

* **我订阅了 Gemini Advanced (个人版) 和 API 有关吗？**
    * **无关。** 你每月支付的 Gemini Advanced 订阅费，是用于 `gemini.google.com` 网页版的，它**不会**为你使用的 API（代码调用）提供任何额度或折扣。

* **用 OpenRouter.ai 这类 API 代理会更便宜吗？**
    * **不会。** 对于调用 Gemini API 来说，**直接使用 Google API（即用即付）永远是最便宜的**。
    * **Google API 是“出厂价”**：你直接付钱给 Google。
    * **API 代理是“零售价”**：他们（中间商）先向 Google 付费，再加上自己的利润，然后再卖给你。你用它是为了**方便**（一个密钥管理所有模型），而不是为了**便宜**。

## 三、 终极指南：如何 100% 防止产生高额费用

当你开启“即用即付”后，最大的恐惧就是“一觉醒来，房子归 Google 了”。仅仅设置 API 限额是**绝对不够的**，它只能防范**突发性**的错误（如代码无限循环），但无法防范**持续性**的低频调用（如每分钟都正常调用 50 次，但跑了 24 小时）。

你必须设置一个“财务保险丝”和一个“技术保险丝”。

### Step 1: 财务保险丝——设置“预算和提醒”（最重要！）

这是你开启“即用即付”后**必须做的第一件事**。它管理的是你的**总金额**。

1.  前往 Google Cloud Console 的 **“结算” > “预算和提醒”** 页面。
    * **直达链接：** [https://console.cloud.google.com/billing/budgets](https://console.cloud.google.com/billing/budgets)
2.  点击“创建预算”，为你当前的项目设置一个预算。
3.  **设置金额：** 设置一个你心理上能接受的小额度，例如 **$10**。
4.  **设置提醒（关键）：** 在“操作”部分，设置“提醒阈值”。
    * **推荐设置：** 当实际支出达到 50% ($5) 和 100% ($10) 时，**“通过电子邮件发送提醒”**。这样你就能在账单失控前收到警告。
5.  **设置终极保险丝（推荐）：**
    * 在“操作”部分，你还可以设置“管理通知”。
    * 选择“将 Pub/Sub 主题与此预算关联”。
    * 你可以通过这个功能，关联一个 Cloud Function，实现在**“账单达到 $10 时，自动关闭此项目的结算功能”**。
    * 这是最强的保险丝，一旦触发，你项目中的所有付费 API 都会停止工作，100% 保证你的花费不会超过 $10。

### Step 2: 技术保险丝——设置“API 配额”

这是你的“技术保险丝”，它管理的是你的**调用速率** (RPM, 每分钟请求数)。

1.  前往 Gemini API 的配额页面。
    * **直达链接 (通用)：** [https://console.cloud.google.com/apis/api/generativelanguage.googleapis.com/quotas](https://console.cloud.google.com/apis/api/generativelanguage.googleapis.com/quotas)
    * *(你需要从下拉菜单中选择你自己的项目)*
2.  在“免费试用”结束后，你将获得**修改配额的权限**。
3.  找到 `Requests per minute` (每分钟请求数) 相关的配额。
4.  点击“修改配额”，**主动将这个值从默认的几千调低**到一个你估算的合理值，例如 **100**。
5.  **好处：** 即使你的代码出现无限循环，它在一分钟内最多也只能调用 100 次，而不是几千次，这极大地降低了你因代码 BUG 导致的瞬间高额花费。

### Step 3: 保持警惕——小心 Google Cloud Console 的其他“吸费陷阱”

Google Cloud 是一个庞大的平台。即使你只想用 Gemini API，你也要小心不要在控制台里“不小心”点开了其他付费服务。

最常见的“陷阱”包括：

1.  **Compute Engine：** 这是“天价账单”的重灾区。千万不要因为好奇而“创建 VM 实例”并忘记关闭它。
2.  **Cloud Storage：** 不要随手上传大型文件（如视频、数据集）并忘记删除。
3.  **Vertex AI：** 这是 Gemini 的“企业版”。它的计费更复杂（例如按“节点小时”收费）。如果你只是个人开发者，请坚持使用 `generativelanguage.googleapis.com` 这个简单的 API，**不要**去 Vertex AI 页面“启用端点”或“训练模型”。

## 总结

对于普通开发者来说，最安全的路径是：

1.  （可选）使用**“免费套餐” (Free Tier)** 进行初步的功能测试，接受它极低的每日限额。
2.  （可选）使用**“免费试用” ($300 赠金)** 来测试 API 的高性能，不用担心付费。
3.  当准备正式使用时，**升级到“即用即付” (Pay-as-you-go)**。
4.  **立刻**前往“结算”页面，设置一个 **$10 的预算提醒（和自动停止操作）**。
5.  **立刻**前往“API 配额”页面，将 **RPM（每分钟请求数）** 主动调低到 100 左右。
6.  **只使用 Gemini API**，不要在控制台里乱点其他你不知道的服务。

通过“财务预算”管住总金额，通过“API 配额”管住突发速率，你就可以安心地使用 Gemini API 了。
